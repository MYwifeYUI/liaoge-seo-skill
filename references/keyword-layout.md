# 关键词布局与关键词—URL映射

## 目标

把完成研究和聚类的关键词分配给最合适的页面，形成关键词—URL唯一主责关系。关键词研究回答“做哪些词”，关键词布局回答“由哪个页面承接”。

## 核心原则

- 以“一页一个主导搜索意图、一个主题簇”为准，不机械限制页面只能出现两三个词。
- 每个重要查询或主题簇指定一个主要目标URL；其他页面可以自然提及，但不能同时承担同一主意图。
- 根据真实客户需求、采购方式和搜索语言规划栏目，不根据内部部门、老板习惯或现有素材目录机械建站。
- 首页承接品牌、企业定位和少量宽泛核心主题；分类/能力页承接中层商业主题；产品、方案、案例和内容页承接具体意图与长尾。
- 没有可靠工具数据时只做分组、意图和业务优先级，不编造搜索量、难度或趋势。

## 金字塔分布

| 层级 | 典型页面 | 承接内容 |
|---|---|---|
| 塔尖 | 首页 | 品牌词、企业定位、少量核心业务主题 |
| 一级 | 产品分类、解决方案、制造能力 | 产品类别、采购场景、应用与核心能力主题 |
| 二级 | 产品详情、工艺、材料、案例 | 具体产品、工艺、材料、规格、项目与应用主题 |
| 塔底 | FAQ、指南、新闻、技术文章 | 问题型、对比型、教程型和项目长尾查询 |

首页不是用来堆放所有高搜索量词。首页主题数量应与品牌定位和真实业务范围匹配；通常聚焦少量核心主题，但不把“2–3个”当作算法规则。

## 布局流程

1. 清洗关键词：统一大小写、单复数、拼写和近义表达；保留原始词用于追溯。
2. 标注意图：Informational、Navigational、Commercial、Transactional，并记录本行业的采购阶段。
3. 建立主题簇：按SERP相似性、问题对象、产品/能力、客户目标和内容格式聚类。
4. 确定页面类型：首页、分类、产品、服务/能力、解决方案、案例、比较、FAQ或知识内容。
5. 指定唯一主责URL：新页面填写建议slug；已有页面填写规范URL。
6. 选择主关键词和辅助词：主词代表主意图，辅助词覆盖同义、属性、问题和实体关系。
7. 检查冲突与空缺：找出同一主题多URL、一个URL混合多个不兼容意图、重要主题无承接页。
8. 规划内链：内容页和案例页链接到对应商业页；分类页链接到下层详情页，详情页回链上层主题页。
9. 排期与验收：按业务价值、意图、可竞争性、素材和页面依赖决定P0–P3。

## B2B询盘站关键词层

至少检查以下八类：

1. 企业定位与品牌词；
2. 产品类别词；
3. 采购与商业调查词；
4. custom、OEM、ODM、manufacturer、supplier；
5. 材料与工艺词；
6. 应用、行业和使用场景词；
7. 痛点、问题、质量与合规词；
8. 图纸、打样、数量、尺寸、表面处理、交期等项目长尾词。

车型、型号或具体产品页可以承接确定需求，但不能取代“可定制制造能力”主线。页面需同时服务技术人员、采购、质量/合规和决策者，并连接到匹配的RFQ路径。

## 搜索意图到页面映射

| 意图 | 用户目标 | 常见承接页 |
|---|---|---|
| 导航型 | 找品牌或已知资源 | 首页、联系页、文档中心 |
| 信息型 | 学习、排错、了解方法 | 指南、FAQ、术语、技术文章 |
| 商业调查型 | 比较供应商、材料或方案 | 解决方案、对比、案例、能力页 |
| 交易/询盘型 | 获取报价、定制、采购 | 产品、服务、落地页、RFQ页 |

不要让同一页面同时主攻互不兼容的信息型和交易型意图。可以在商业页面回答必要问题，但首要内容格式和行动路径必须服从主导意图。

## 内部竞争诊断

不能仅凭多个页面包含同一词就判定关键词蚕食。满足以下多项才提高风险判断：

- 多个URL的Title、H1和正文都面向同一主意图；
- Google在同一查询上频繁切换排名URL；
- 多个URL获得相似查询曝光但没有稳定主页面；
- 页面内容高度重复，外链和内链信号被分散；
- 目标页面排名或转化在新相似页面上线后下降。

使用GSC页面×查询数据、SERP观察、抓取结果和内容对比共同判断。`site:域名 关键词`只能帮助发现候选页面，不能单独证明处罚或内部竞争。

处置顺序：

1. 明确最符合意图、内容最完整、转化路径最佳的规范页面；
2. 对互补页面重新定位主题与Title/H1；
3. 对高度重复页面合并内容，并在合适时做301；
4. 修正canonical、导航、面包屑和内链锚文本；
5. 在GSC持续观察目标URL是否稳定。

## 长尾覆盖

- 不为每个词形或极小变体单独建页；一个完整主题页可覆盖大量相关长尾。
- 只有当SERP意图、产品属性、地域/车型/应用和内容需求确实不同，且能提供独特价值时才拆页。
- 程序化页面必须有可靠数据、独特内容、有效内部链接和明确用户价值；避免生成大批薄页。
- 问题型、定义型、对比型和清单型内容可同时服务传统SEO与GEO，但需要明确答案、证据、实体关系和可引用结构。

## 优先级

可以按1–5分评估并保留原始数据口径：

- 业务相关度：30%
- 可竞争性：25%（难度越低得分越高）
- 搜索需求：20%
- 意图/询盘价值：15%
- 趋势：10%

综合分仅用于排期，不能伪装成Google官方指标。对新B2B站，业务相关度、真实承接能力、素材准备和转化路径可以覆盖纯搜索量排序。

## 标准交付表

至少包含：

| 字段 | 说明 |
|---|---|
| Keyword / 关键词 | 原始查询 |
| Cluster / 主题簇 | 聚类后的主题 |
| Intent / 意图 | 信息、导航、商业调查、交易 |
| Funnel / 决策阶段 | 认知、评估、询盘 |
| Primary URL / 主责URL | 唯一主要承接页 |
| Page Type / 页面类型 | 首页、分类、产品、方案、案例、内容等 |
| Primary Keyword / 主关键词 | 页面主题代表词 |
| Supporting Keywords / 辅助词 | 同义、属性、问题和实体词 |
| Priority / 优先级 | P0–P3及理由 |
| Status / 状态 | 保留、优化、新建、合并、重定向 |
| Internal Links / 内链 | 上下游页面和建议锚文本 |
| Evidence / 数据来源 | GSC、关键词工具、SERP或用户资料 |

最终同时输出：关键词—URL表、金字塔/网站结构、冲突处理表、内容空缺、内链方案和分阶段排期。
