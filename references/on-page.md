# 页面优化（第5章精华）

> 页面和网站结构是 SEO 人员可以控制的。页面关键位置出现目标关键词是基本思路；标题标签是第一个关键位置。

## 1. 页面标题（Title）——最重要的因素

- 独特不重复：每页一个独特标题；大站用模板生成（产品名/文章标题 – 分类 – 网站名），翻页页加页码；首页人工撰写。
- 准确相关：不要加与本页无关的热门词（20 年前管用，现在会被当作弊）。
- 字数：百度约 30 个中文字（60 字节内），Google 约 65 英文字符（约 32 个中文字）；建议标题不超过 25-30 个中文字。超出部分被截断、权重降低。
- 简练通顺、不要堆砌关键词：写成正常通顺的句子（百度百科是范本）。
- **关键词放在最前面**：位置越靠前通常排名越好；标题 = 倒置的面包屑（"产品名 – 分类 – 网站名"）。
- 吸引点击：点击率是搜索流量的另一个决定因素（排名 + 点击率 = 流量）。
- 组合 2-3 个关键词（最多 3-4 个）：并排或组合成通顺词组/句子（"SEO技术、SEO教程"写成通顺的一句）。
- 公司/品牌名称放最后；品牌词重要的网站可只写品牌。
- 连词符用 `-` 或 `|`（视觉差异，排名无区别）。
- 重要页面（首页、分类、热卖产品）人工撰写。

## 2. 描述标签（Description）

- 不用于排名计算，**影响点击率**（大部分情况下摘要来自描述标签）。
- 约显示 77 个中文字（英文 156 字符）；建议不超过 70 个中文字。
- 准确、通顺、吸引点击、每页独特；不要与标题重复、不要堆砌关键词（否则搜索引擎动态抓取摘要，你就失去了控制）。
- 大站自动生成：提取正文第一段 / 按产品信息模板生成。
- 不能生成通顺不重复的描述时，宁可不写。

## 3. 关键词标签（Keywords）

- 所有主流搜索引擎都不再使用；**不用浪费时间写**。

## 4. 正文优化

- 词频/关键词密度：与排名已无直接联系；自然写作即可——短页面出现 2-3 次、长页面 4-6 次关键词就够，千万不要堆积。
- **前 50-100 个词**：第一段文字出现关键词（自然写作的必然结果：开头点题）。
- **关键词变化形式**：同义词、近义词、不同称呼交叉出现（电脑/计算机、笔记本/手提电脑）。
- **词组邻近度**：关键词组完整、按顺序出现几次（百度对完整匹配要求比 Google 高）。
- **词组拆分出现**：不仅完整出现，单个词也分别出现。
- **语义相关词**：相关概念词自然融入。
- 分类页面要有说明文字（不要空白列表页）。
- 总原则：**自然写作**。不要时刻想着密度、同义词、语义词，那效率太低；头脑中有"关键词在重要位置的分布 + 自然融入"的意识即可。

## 5. H 标签

- H1 重要性仅次于 Title（近两年权重降低，但仍是文章结构的重要信号）。
- 一篇文章只有一个 H1，包含最重要关键词；小标题用 H2（可含辅助关键词）；H3 以下权重已很低。
- 不要滥用（整篇都用 H 标签 = 没用 H 标签）。

## 6. ALT 文字

- 准确描述图片内容 + 出现一次目标关键词；不要堆积、不要与 Title 一样。
- 图片做链接时 ALT = 锚文字（公司 logo 的 ALT 含首页关键词，它通常是第一个链接到首页的链接）。
- 对百度很重要（图文展现大量出现）。

## 7. 精简代码

- CSS/JS 放外部文件；减少注释；少用表格布局。
- 文件大小：百度建议 HTML ≤ 128KB；Google 建议 ≤ 100KB、页面上链接 ≤ 100 个；文件太大只索引前半部分。
- 精简代码 = 降低搜索引擎提取文字难度 + 提高打开速度。

## 8. 内部链接及锚文字

- 内链锚文字完全由站长控制，是提高相关性的重要手段；锚文字多样化、自然，避免过度优化（完全匹配锚文字集中是惩罚原因之一）。
- 不要为加内链而在正文硬塞链接；只在确实帮助用户理解时加。
- 谨慎使用"文章出现关键词自动插链接"的 CMS 功能（很难自然）。

## 9. 导出链接

- 链接到相关的高质量网站不降低自己权重，还能提升自己页面的相关性（做"枢纽页面"）；大量链接向垃圾网站才有危险。

## 10. 黑体/斜体、页面更新、社交按钮

- 黑体/斜体有一点点强调作用（权重极小），有时帮助分词。
- 页面更新：Google 有 Query Deserves Freshness（时效性查询给新内容更高权重）；更新旧文章有效，但只改发布时间会被判作弊。
- 放社交分享按钮，用户参与数据可能被用于判断页面质量。

## 11. 页面用户体验与 Core Web Vitals

- 相关算法：百度石榴（垃圾广告页）、冰桶（移动体验）、闪电（速度）；Google Page Layout（首屏广告）、App 插页惩罚、移动插页惩罚、移动速度更新、Page Experience。
- 用户体验要点：页面打开快；内容安全（无病毒/钓鱼/欺骗）；https；弹窗/插页谨慎（百度、Google 都打击干扰性插页）；易读字体；实质内容在最显眼位置、第一屏就有实质内容；广告与内容清晰区分；首屏广告不超过页面的 1/3；能用图片/视频帮助理解就做。
- **Core Web Vitals**：LCP（加载，<2.5 秒）、INP（互动，2024 年 3 月替代 FID）、CLS（布局稳定，<0.1）；图片不设置尺寸是 CLS 最常见原因；在 GSC 查看、PageSpeed Insights 优化。

## 12. 结构化数据标记

- schema.org（2011 年 Bing/Google/Yahoo 发起），推荐 **JSON-LD** 格式。
- 对中国网站最有用的是产品页：名称、URL、图片、描述、SKU、品牌、价格、平均星级、评论数、有货状态等。
- 不是排名因素，但强烈建议添加（帮助理解 + 富摘要 + 点击率）；不能保证显示富摘要。
- 百度不支持 Schema 结构化数据（用资源平台 sitemap/开放平台）。

## 13. 提高页面速度

- 速度是排名因素，也直接影响转化（书中案例：Cook 减 850ms → 转化率 +7%、跳出率 -7%；BBC 每慢 1 秒丢 10% 用户；Modify 首页减 100ms → 转化 +1.11%）。
- 步骤：
  1. 检查服务器速度（百度资源平台抓取时间、GSC、多点测速工具）；
  2. **图片优化**（图片占下载量 50%-90%）：用 jpeg/png/gif/WebP，不要超尺寸超清晰度，不要直接放原图；
  3. **GZIP 压缩**；
  4. **浏览器缓存**（HTML/CSS/JS 1-2 周、图片可 1 年）；
  5. **JS 延迟加载/异步**（渲染阻塞）；
  6. 图片懒加载（Chrome 已自动支持）。
- 工具：PageSpeed Insights（诊断+建议）、webpagetest（瀑布流看瓶颈）。
